# Задание: Джарвис как полноценный ИИ-ассистент на ПК (версия 3.4)

Это рабочий промт для разработчика (в том числе для Claude) по общей идее владельца. Его задача — сделать из
Джарвиса помощника, который отвечает сразу, позволяет себя перебивать, управляет компьютером почти как человек
и принимает задания из Telegram.

## 1. Кто пользователь и чего он хочет

- Один владелец, Windows 10/11, русский язык, обращение «сэр». Не программист: никаких bat-файлов, консолей и веб-окон.
  Всё настраивается в окне программы, обновления приходят сами.
- Главная боль: «думает три века». Ответ должен начинаться почти сразу, а не после полного обдумывания.
- Джарвиса можно перебить: он говорит, владелец задаёт уточнение — Джарвис замолкает и сразу отвечает на новое.
- Задачи из Telegram: написал боту с телефона — Джарвис на домашнем ПК выполнил и прислал результат
  (текст, скриншот, файл).
- «Уметь всё, что может ИИ на ПК»: заметки в папке, создать/открыть/закрыть папку, окна программ, найти что-то
  в интернете и пересказать, мелкие задачи, рутина по шаблону, который даёт владелец.

## 2. Что известно из открытых проектов (и что из этого берём)

| Источник | Идея | Как применяем |
|---|---|---|
| [KoljaB/RealtimeSTT](https://github.com/KoljaB/RealtimeSTT) | VAD нарезает речь, распознавание начинается ещё до конца паузы (early transcription), второй проход уточняет | Распознаём «на всякий случай» уже через 300 мс тишины; если человек не продолжил, текст готов к концу паузы |
| [KoljaB/RealtimeTTS](https://github.com/KoljaB/RealtimeTTS) | Текст модели идёт потоком, озвучка начинается с первого предложения | Модель отвечает потоком (SSE), каждое готовое предложение сразу синтезируется; следующее синтезируется, пока играет предыдущее |
| [huggingface/speech-to-speech](https://github.com/huggingface/speech-to-speech) | Перебивание: VAD работает и во время ответа; при начале речи пользователя ответ отменяется, генераторы проверяют флаг `interrupted` | Микрофон больше не глушится во время ответа; новая фраза отменяет текущий ответ (поток модели и звук) |
| NVIDIA Riva / voice agent FAQ | Без подавления эха ассистент перебивает сам себя | Эхо отсекаем трижды: повышенный порог громкости во время своей речи, сравнение услышанного с тем, что сейчас говорится, и режим «перебивать только по имени» для колонок |
| Open Interpreter | Модель сама вызывает инструменты ПК в цикле | Уже есть встроенный движок (`agent.py`) — расширяем набор команд |
| Telegram Bot API, разборы ошибки 409 | Только один `getUpdates` на токен; шлюз Hermes и наш бот не могут опрашивать одного бота | Свой бот внутри Джарвиса (long polling, без лишних библиотек); при 409 — понятная подсказка «остановите шлюз Hermes» |
| Боты удалённого управления ПК (Tostapunk/PC-Control-telegram-bot и др.) | Белый список ID, команды /screen, /status | Привязка по коду из окна (не надо искать свой ID), белый список, команды `/screen /status /stop /tasks` |
| DuckDuckGo HTML (`html.duckduckgo.com/html/`) | Поиск без ключа API: `.result__a`, `.result__snippet` | `web search` и `web read` в jarvis-pc, ссылки `uddg=` раскодируются |
| Shell.Application (PowerShell) | `Windows()` + `LocationURL` + `Quit()` закрывает конкретное окно проводника | `folder close` |

## 3. Архитектура реального времени

```
микрофон (всегда слушает) ─► VAD ─► «черновое» распознавание на 300 мс тишины ─► окончательная фраза
                                                                                     │
         ┌───────────── во время ответа: эхо-фильтр, «стоп»-слова, перебивание ◄──────┤
         ▼                                                                           ▼
   отмена текущего хода (модель + звук)                         новый ход (Turn) в своём потоке
                                                                  quick → движок (поток) → Hermes
                                                                         │ предложения
                                                                         ▼
                                                    очередь речи: синтез N+1, пока играет N
                                                    (PyAV mp3 → PCM → sounddevice, громкость/стоп мгновенно)
```

Требования:
- Ход (`Turn`) — отдельный поток с собственным флагом отмены. Новый ход отменяет старый. Слушающий цикл никогда
  не блокируется ответом.
- `llm.stream_chat` — поток SSE с таймаутами на подключение и на паузу между кусками; не поддерживается сервером —
  обычный запрос.
- `agent.Agent.ask(..., on_text=...)`: строки `ДЕЙСТВИЕ:` не озвучиваются; обычный текст отдаётся по предложениям.
- Плеер: PCM через `sounddevice.OutputStream`, `stop()` и `duck()` за ≤50 мс; при ошибке — прежний MCI; при отсутствии
  сети — голос Windows.
- Распознавание: `without_timestamps`, без повторного VAD внутри Whisper, `beam_size=1`, пауза конца фразы 600 мс.
- Перебивание (настройка «Слух → Перебивание»): «голосом» (по умолчанию: любая фраза ≥2 слов, не похожая на эхо),
  «только по имени», «выключено». «Стоп», «хватит», «замолчи» всегда останавливают речь.
- Во время ответа и 12 с после него имя говорить не нужно (режим разговора).

## 4. Telegram

- Свой модуль `jarvis/telegram.py`: long polling (`timeout=25`), стандартная библиотека, отдельный поток, переподключение
  с паузой, корректная остановка.
- Токен — в окне (страница «Telegram»), хранится локально, в журналах и отчётах скрыт.
- Привязка: окно показывает 6-значный код, владелец пишет его боту — его ID добавляется в белый список.
  Чужим бот не отвечает вообще (кроме подсказки «отправьте код из окна Джарвиса», пока список пуст).
- Текст → тот же движок, что и голос (с командами ПК). Голосовое → распознаётся локально тем же Whisper.
  Пока идёт работа — «печатает…» и сообщение со списком выполняемых шагов, которое обновляется.
- Ответ — текстом; по желанию ещё и голосом (mp3). Файлы и скриншоты: модель может вызвать `send <путь>`,
  бот пришлёт файл. Присланные владельцем файлы сохраняются в `Загрузки\Джарвис из Telegram`, путь передаётся модели.
- Команды: `/start`, `/help`, `/screen`, `/status`, `/stop`, `/tasks`, `/routines`, `/run <шаблон>`, `/voice on|off`.
- 409: понятная причина в окне и в «Диагностике» (одновременно работает шлюз Hermes), кнопка «Остановить шлюз Hermes».

## 5. Возможности на ПК (jarvis-pc и движок)

- `notes add|list|read|search|open` — заметки `.md` в папке (по умолчанию `Документы\Заметки Джарвиса`, меняется в окне).
- `folder open|close|create` — по пути или по имени: рабочий стол, загрузки, документы, изображения, музыка, видео.
- `windows list`, `window close|focus <название>` — видеть открытые окна и управлять ими.
- `web search <запрос>`, `web read <адрес>` — поиск и чтение страницы, пересказ делает модель.
- `keys type <текст>`, `keys press <сочетание>` — ввод в активное окно.
- `apps <запрос>` — найти установленную программу в меню «Пуск»; `open` использует его, если имя не из таблицы.
- Шаблоны рутин: `%APPDATA%\Jarvis\routines\<имя>.md` — заголовок и шаги обычным языком, переменные `{дата}`,
  `{время}`, `{вчера}`. Запуск: голосом «выполни шаблон …», в Telegram `/run …`, кнопкой в окне. Создать: в окне
  или попросить Джарвиса («сохрани шаблон утро: …»). Выполняет встроенный движок шаг за шагом с увеличенным лимитом.
- Безопасность: прежние запреты (системные папки и процессы, format/diskpart/shutdown), удаление — в корзину,
  набор текста не работает в окнах входа и паролей.

## 6. Критерии приёмки

1. Быстрая команда («громче») — ответ ≤0,5 с после распознавания.
2. Вопрос к модели — первое озвученное слово примерно через «время первого токена + 1 с», не после полного ответа.
3. Фраза во время речи Джарвиса прерывает её; собственный голос из колонок не считается перебиванием (тест на эхо).
4. «Стоп» во время речи — тишина ≤0,2 с (на уровне кода: плеер останавливается сразу).
5. Telegram: код привязки, текст, голосовое, `/screen`, `send` файла, 409 с подсказкой — покрыто тестами на
   поддельном сервере Bot API.
6. Новые команды jarvis-pc есть в `agent.CATALOG` и в `pc.build_parser()` (тест), работают в сухом прогоне.
7. `python tools/doctor.py --strict` и все тесты проходят; релиз собирается в CI.
